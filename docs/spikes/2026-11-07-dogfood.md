The check cost is the finding. One commit touched `check.py`, which six of the seven ADRs name in
`Applies to`, so the same 100k-token diff was sent seven times and written to cache seven times.
Separate `claude -p` sessions cannot share a cached diff: the prompt is one user message, so the cache
prefix diverges at the first ADR-specific byte. The only lever that works inside `claude -p` is one judge
call per commit carrying every selected ADR (bead adrcheck-c6l.1). Expected: about $0.35 for this commit
instead of $2.00. With a direct API adapter (adrcheck-oao) the diff can be its own cached block instead.

## What the run teaches

1. **The judge over-abstains on reflow diffs.** Three UNCLEAR rows have the same shape as the job-search
   second-opinion finding: the diff touches a file the ADR governs, the changed lines are a reformat, and
   the obligation is not touched. The honest verdict is COMPLIANT ("this change does not affect the
   obligation"), and a relevance gate (adrcheck-c6l) would have removed all three before the judge ran.
   Three of nine judged rows is a 33% abstention rate on a commit that could not have conflicted.
2. **The report hides relevant=false.** ADR-2 and ADR-7 were selected and judged for 659695c, and the
   judge said the ADR has nothing to do with the change. The markdown renderer prints findings only, so a
   reader cannot tell "judged, not relevant" from "not selected". Cost was paid for a line that is not
   shown. Filed under adrcheck-rnr.
3. **Dotted anchors produce false stale alarms.** The ADR text says "the `RepoReader.contains()` probe",
   the compiler copied it, the code calls `repo.contains`. Fix in the compile prompt (anchors are names as
   code spells them: a bare identifier, a path, or a literal string), which bumps PROMPT_VERSION under
   ADR-4/5 and recompiles for about $0.42. Not fixed by hand in the cache, by the rule in adrcheck-dzz.
4. **Selection by `Applies to` is too coarse for a hub file.** `check.py` is named by six ADRs, so any
   edit to it costs six judge calls. Per-commit batching (adrcheck-c6l.1) fixes the cost; the gate fixes
   the noise. Both are now backed by a measured row, not an estimate.

## Decisions taken in this run

- The obligation cache stays at `.adrcheck/obligations/` and is committed from this commit on. ADR-4/8
  says the cache is safe to commit; the entries hold obligations only (no paths, no times, no user). CI
  therefore judges without compiling. Entries for superseded ADR text are left behind when an ADR changes;
  a `compile --prune` is needed before that becomes untidy (noted in adrcheck-dzz).
