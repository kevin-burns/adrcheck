# Same model, two routes: Haiku 5.5 through `claude -p` and through OpenRouter, 2026-11-09

Question from Kevin: run Haiku through the Claude CLI as well, and time it. Same corpora, same cached
obligations, same prompts from adrcheck; the only difference is whether the request goes through
`claude -p --model haiku --tools ""` or as a plain `chat/completions` POST to OpenRouter. The CLI's `haiku`
alias resolved to `claude-haiku-5-5` (read from the CLI's own `modelUsage` field), so the model is the same.
Four runs in parallel on one machine.

| Corpus | Route | Score | Tokens in / out | Cost | Wall |
|---|---|---|---|---|---|
| planted, 7 calls | claude-cli | 8/9 | 365,619 / 14,434 | $0.028 reported | 94 s |
| planted, 7 calls | OpenRouter | 9/9 | 10,593 / 6,759 | about $0.004 | 34 s |
| adrcheck, 1 call | claude-cli | 9/11 | 109,648 / 12,822 | $0.142 reported | 57 s |
| adrcheck, 1 call | OpenRouter | 11/11 | 58,930 / 6,413 | about $0.009 | 29 s |

Run files beside this page: `.cli-route.cli-haiku-planted.run.json`, `.cli-route.or-haiku-planted.run.json`,
`.cli-route.cli-haiku-adrcheck.run.json`, `.cli-route.or-haiku-adrcheck.run.json`.

## The overhead, measured directly

A two-token prompt through `claude -p --model haiku --output-format json` reported 2 input tokens, 33,758
cache-creation tokens and 11,382 cache-read tokens, 899 ms of API time, and a cost of $0.0069. That is the
CLI's own system prompt, present on every call even with `--tools ""`. It accounts for the fixed gap in the
token column: about 51,000 a call on the planted corpus against 1,500 through the API. The earlier spike
inferred this from the totals; this is the measurement.

## The behaviour, which was the surprise

The CLI route was not only slower and dearer. The same model turned three rows UNCLEAR that it had called
COMPLIANT through the API, with reasons of the form "the type of `minor_units` is defined in
libs/money/money.py, which is not among the provided files" and "the post-change files are unavailable, so I
cannot confirm". Through the API the same prompt and the same model did not ask for those files. The one
variable is the system prompt the CLI puts in front of adrcheck's. It appears to make the model more
cautious about what it has not been shown. A reasonable trait in a coding agent; in a judge whose prompt
already tells it what it has, it is noise, and it moved two corpora from full marks to 8/9 and 9/11.

Not a controlled experiment of the CLI's prompt, which adrcheck cannot see. What is established: with the
model held equal, the route changed the verdicts.

## What follows

- The judge seat belongs on the API route: `anthropic:` with a key, or `openai:` through OpenRouter. The
  CLI route is the zero-setup default for a developer who is logged in, and the eval numbers for it should
  be read as a different judge, not the same one at a different price.
- Wall time through the CLI is about three times the API route for the same calls on this machine, from
  process start and the system prompt rather than the model.
- The reported cost per CLI call includes the overhead, which is why a trivial prompt costs $0.007 and why
  the adrcheck corpus call cost $0.14 against about a cent via OpenRouter.
